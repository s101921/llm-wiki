# 多模態 LLM

**多模態 LLM 的核心創新：把圖片、音訊、影片也壓縮成向量 embedding，讓 LLM 像閱讀文字一樣閱讀它們。**

> 關鍵原則：所有輸入（文字、圖片、音訊、影片）都轉換成「嵌入向量序列」，讓同一個 Transformer 架構可以跨模態推理。

## 整體架構：三個關鍵元件

```
原始輸入（圖片/音訊/影片）
        ↓
  [模態編碼器]  ← 把內容壓縮成向量
        ↓
   [投影層]    ← 換算成 LLM 懂的維度
        ↓
  [LLM 主幹]  ← 用注意力機制整合所有 token，輸出文字
```

### 元件 1：模態編碼器（Modality Encoder）

- 圖片 → Vision Transformer（ViT）/ CLIP
- 音訊 → Whisper / HuBERT
- 影片 → 視覺編碼器 ＋ 音訊編碼器（分開處理再合併）

### 元件 2：投影層（Projection Layer）

將不同維度的向量換算成 LLM 能接受的格式（768 維 → 4096 維），同時**對齊語意空間**，讓「狗的圖片向量」和「狗這個字的向量」住在相近的位置。

### 元件 3：LLM 主幹（Backbone）

接收所有 token 序列，透過自注意力機制整合所有資訊，輸出回答。**對 LLM 來說，圖片 token 和文字 token 一視同仁，全部都是一串向量。**

## 模態編碼器的訓練方式：對比學習

以 CLIP（OpenAI）為例：在 **4 億筆「圖片＋文字說明」配對資料**上預訓練。

```
正確配對圖文向量 → 空間距離拉近 ✅
錯誤配對圖文向量 → 空間距離推遠 ❌
```

結果：在「共享嵌入空間」中，相同概念的圖片向量和文字向量住在相近位置，不同概念住得很遠。

## 圖片如何切割成 Token

```
原始圖片（224×224 像素）
        ↓
切成 14×14 的小方塊（patch），共 196 塊
        ↓
每塊攤平成一個數字向量（例如 768 維）
        ↓
196 個向量排成一列 = 196 個視覺 token
```

音訊同理：聲波 → 頻譜圖 → 切成 patch → 向量。

## LLM 讀取視覺 token 的兩種方式

**方法 A：直接拼接（最常見）**
```
[圖片token_1][圖片token_2]...[圖片token_196][文字: 這張圖裡有什麼？]
```

**方法 B：交叉注意力（Cross-Attention）**
圖片 token 不進入序列，透過交叉注意力層讓文字 token 「詢問」圖片資訊。LLaMA 3.2 採用此方式。

## 「先轉文字」vs「直接 Embedding」

| 比較項目 | 舊方法（先轉文字） | 現代多模態 LLM |
|----------|-------------------|----------------|
| 圖片處理 | OCR 辨識成文字 | 直接編碼成視覺向量 |
| 音訊處理 | ASR 語音辨識成文字 | 直接編碼成聲音向量 |
| 資訊保留 | 損失非語言資訊 | 保留完整視覺/聽覺語意 |
| 代表模型 | 早期 pipeline 系統 | GPT-4o、Gemini、Claude |

> ⚠️ 例外：某些系統仍用 Whisper 先轉文字再送 LLM，簡單但會損失語氣、音樂、環境音等非語言資訊。

## 每個圖片 Token 代表什麼？

每個 token 不是單一物件，而是**多個概念的加權混合體**：

```
狗尾巴區塊的 patch token ≈
  1.79 × "狗" + 1.21 × "可愛" + 1.11 × "毛皮" + 0.71 × "黑色" + 0.32 × "尾巴"
```

## 影片的特殊處理

影片 = 視覺幀 ＋ 音訊，兩者需時間對齊後合併送入 LLM 主幹。

## 重點摘要

1. 多模態 LLM **不是把圖片轉成文字**，而是轉成向量 token
2. 模態編碼器靠**對比學習**訓練——語意相近的圖文向量住在空間中相近位置
3. 投影層把不同模態向量換算成 LLM 能接受的格式，**同時對齊語意空間**
4. LLM 主幹用注意力機制整合所有 token，圖文一視同仁
