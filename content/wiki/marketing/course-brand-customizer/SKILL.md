# 課程品牌客製化技能

## 目的
幫助講師在上課前，快速將「AI解放行銷力完整提示詞」公版，替換成學員企業的品牌資訊，同時根據學員的部門職能調整情境，讓每個章節的 AI 工具示範都貼近他們的日常工作。

## 執行流程

### Step 0：解析已有資訊 → 判斷缺口 → 按需詢問

**先做：解析講師已提供的所有內容**（文件 / 網址 / 貼上的文字 / 對話中提及的內容），嘗試從中提取：
- ① 品牌名稱、產業、產品線
- ② 學員部門或職能（如有提及）
- ③ 學員的日常工作任務或情境（如有描述）

**再做：根據提取結果判斷缺口，決定是否需要詢問**

| 情況 | 處理方式 |
|---|---|
| 品牌資訊充足 ＋ 部門明確 | 直接進入 Step 1，不需詢問 |
| 品牌資訊充足 ＋ 部門未提及 | 只問一件事：學員的部門 |
| 品牌資訊不足 ＋ 部門明確 | 只問一件事：品牌資訊（官網或文件）|
| 品牌資訊不足 ＋ 部門未提及 | 一次問齊兩件事 |

**「部門明確」的判斷標準：**
- 明確：文件中出現「業務團隊」「PM」「客服部」「行銷部」等字眼，或描述了日常工作任務
- 不明確：只提到職稱但無法判斷主要職能（如「主管」「專員」）→ 需補問
- 未提及：完全沒有部門相關資訊 → 需補問

**詢問模板（按缺口選用）：**

只問部門：
```
我已從您提供的資料中整理好品牌資訊，還需要確認一件事：
學員主要的部門或職能是？
□ 行銷 / 品牌
□ 業務 / 銷售
□ 產品 / PM
□ 客服 / 客戶成功
□ 後勤 / 營運
□ 人資 / 培訓
□ 其他：＿＿＿
```

問齊兩件事：
```
在開始客製化之前，需要確認兩件事：
1. 學員的公司 / 品牌（或提供官網連結、品牌文件）
2. 學員的部門或職能？（行銷 / 業務 / PM / 客服 / 後勤 / 人資 / 其他）
```

**部門資訊不足時的預設：** 若講師要求直接開始且不提供部門資訊 → 預設為行銷部門，維持原版情境。

### Step 1：收集品牌與部門情境資料（僅供內部使用，不輸出）

**品牌資料來源優先順序（可混用）：**
1. 使用者提供的文件（PDF / Word / 貼上的文字）→ 直接解析
2. 使用者提供的網址 → 用 web_fetch 抓取
3. 使用者只提供品牌名稱 → 用 web_search 搜尋

**必須搜集的品牌資訊清單：**
- 品牌官網、品牌介紹、品牌調性 / 核心價值 / Slogan
- 主力產品線清單（列出所有主要部門或產品線）
- 各產品線的近期新品（優先使用新品；無新品則用主力商品）
- 目標受眾 / 客群（可依產品線分別描述）
- 近期行銷活動（如有）

**同步搜集學員部門的日常任務情境：**

| 部門 | 需額外了解的資訊 |
|---|---|
| 業務/銷售 | 客戶開發流程、銷售情境、競品比較、異議處理 |
| 產品/PM | 產品週期、需求蒐集、用戶研究、跨部門溝通 |
| 客服/客戶成功 | 客訴類型、服務流程、知識庫需求、客戶分級 |
| 後勤/營運 | 供應鏈、庫存管理、跨部門協調、SOP建立 |
| 人資/培訓 | 招募、員訓、績效管理、職位說明書 |
| 行銷/品牌 | 維持原版情境，無需額外調整 |

**⚠️ 重要：以上所有資料僅作為替換佔位符的內部依據，不得出現在 Notion 筆記的任何位置。**

### Step 2：規劃各章節的情境化方向與產品分配

在替換前，制定兩份計畫：

**2A. 部門情境對應表**（若為非行銷部門，列出每個 Part 的情境轉化方向）

以下為各部門的情境對應參考（實際應依品牌性質調整）：

| 章節 | 行銷（原版） | 業務/銷售 | 產品/PM | 客服/客戶成功 | 後勤/營運 | 人資/培訓 |
|---|---|---|---|---|---|---|
| **Part 1** 指令描述立體性 | 社群貼文創作 | 客戶開發開場白 / 提案信 | 功能需求說明書 | 客訴回覆信件 | 供應商詢價信 | 職缺描述撰寫 |
| **Part 1** 評分引導法 | 文案品質評分 | 提案說服力評分 | 需求文件清晰度評分 | 客服回覆品質評分 | SOP 可執行性評分 | 培訓教材評分 |
| **Part 2** 競爭者分析 | 競品品牌分析 | 競爭對手業務策略分析 | 競品功能比較 | 同業客服體驗比較 | 供應商/服務商比較 | 同業薪酬與福利比較 |
| **Part 2** 消費者洞察 | 目標受眾人物誌 | 目標客戶決策者人物誌 | 目標用戶使用情境 | 高風險流失客戶輪廓 | 關鍵供應商特性 | 理想求職者人物誌 |
| **Part 2** 溝通主軸 | 廣告溝通主軸 | 銷售話術 / 核心賣點 | 產品定位陳述 | 服務承諾宣言 | 流程改善提案架構 | 雇主品牌溝通主軸 |
| **Part 3** 圖像生成 | 廣告視覺 | 提案簡報視覺 | 產品介面原型示意圖 | 服務流程圖 / 說明圖 | 倉儲/物流場景示意 | 培訓教材視覺 |
| **Part 4** 數據分析 | 廣告成效分析 | 銷售漏斗分析 | 用戶行為數據分析 | 客訴趨勢分析 | 庫存/供應鏈數據分析 | 員工滿意度/留任率分析 |
| **Part 5** AI 代理數據 | 爆品趨勢發掘 | 潛力客戶評分 | 功能優先級排序 | 自動分派工單 | 異常訂單偵測 | 自動篩選履歷 |
| **Part 5** AI 代理圖片 | 品牌視覺系統 | 業務簡報視覺 | 產品 Mockup 批量生成 | 服務說明圖製作 | 標準化文件視覺 | 培訓教材視覺系統 |

**2B. 各 Part 的產品分配計畫**

在開始替換前先內部確定，遵守以下分組規則：

**⚠️ Part 2 三個單元必須使用同一產品（強制規則）**

Part 2 的「競爭者分析」→「消費者洞察」→「溝通主軸」是一條完整的分析鏈：
- **競爭者分析** 從競品中找出該產品的獨家賣點（Key Selling Point）
- **消費者洞察** 建立目標受眾人物誌，推導消費者洞察（Consumer Insight）
- **溝通主軸** 將上述兩個分析結果作為輸入，代入公式：KSP + CI = Communication Theme

三個單元的產品不一致，公式的輸入源就會錯亂，課堂邏輯無法串聯。

```
Part 1        → [產品A]（新品優先，主力商品次之）
Part 2 全部   → [產品B]（三個單元統一使用同一產品）
              ├─ 競爭者分析 → 產品B 的市場競爭格局 → 得出 KSP
              ├─ 消費者洞察 → 產品B 的目標受眾研究 → 得出 CI
              └─ 溝通主軸  → KSP + CI → Communication Theme
Part 3 JSON示範 → [產品C]（與 Part 2 不同，展示視覺多樣性）
Part 3 課程示範 → 保留原版，不替換
Part 4        → [產品D]（選有具體數據/指標的產品）
Part 5        → [產品E]（選適合規模化 AI 代理的產品）
```

各 Part 之間（A/C/D/E）盡量選用不同產品；Part 2 的產品B 可與其他 Part 相同或不同，但 Part 2 **內部三個單元必須統一**。

### Step 3：識別需替換的佔位符

公版中所有需要替換的變數都用 **`[方括號]`** 標示。

**可替換的佔位符類型：**

| 佔位符類型 | 行銷版範例 | 非行銷版替換方向 |

| 任務/目的 | `[社群行銷]專家` | `[客服回覆]專家` / `[業務開發]專家` |
| 產業/市場類型 | `[台灣的 OTT 串流影音平台市場]` | `[學員所在產業]` |
| 品牌名稱 | `[LINE TV]` | 學員品牌名稱 |
| 主力產品/服務 | `[亞洲戲劇（台劇、韓劇...）]` | 該 Part 分配的產品/服務 |
| 目標客群 | `[18–45 歲...喜愛亞洲流行文化]` | 依部門調整（客戶/用戶/求職者等）|
| 情境描述 | `激活休眠玩家回歸` | 依部門調整（如：跟進沉睡客戶）|
| 分析對象 | `[台灣的 OTT 串流影音平台市場]` | 依部門調整（如：競爭對手業務手法）|
| 洞察人物誌 | `[25至40歲...送禮的消費者]` | 依部門調整（如：企業採購決策者）|
| 品牌個性 | `[專業可靠 × 輕鬆隨性]` | 品牌調性（不因部門改變）|
| 產品賣點 | `[EH-NA0K 搭載...]` | 該 Part 分配產品的核心賣點 |
| 消費者洞察 | `[對於30-45歲...]` | 依部門調整後的目標對象洞察 |
| 溝通渠道 | `[Threads]` | 依部門調整（如：Email / LINE官方帳號）|
| 數值/指標 | `[3]`, `[8]`, `[7]` | 保留原數值，不替換 |

**⚠️ 保留規則（以下內容一律不替換、不刪除）：**
- `[括弧內為操作說明]` 的指示文字（如：`[請說明：如提升銷售/降低成本等]`）
- 標示「課程示範」的 code block → 完整保留原範例，一字不改
- 標示「公版內容」的 code block → 完整保留原內容，一字不改
- 所有延伸思考、指令描述、callout 說明性段落
- 評分數值（`[8]`, `[7]` 等）與技術指令（Python 語法等）
- 章節標題、圖示（💡）、顏色標籤（{color="..."}）

### Step 4：替換公版內容

依照 Step 2 的計畫，逐 Part 替換佔位符，同時根據學員部門調整情境。

**各 Part 替換重點：**

| Part | 替換目標 | 非行銷部門注意 |
|---|---|---|
| **Part 1** | 專家角色、行銷目標、受眾、主打商品、特點、渠道、檔期；評分維度改為部門對應指標 | 渠道→溝通工具；檔期→執行時程 |
| **Part 2 競爭者** | 市場類型、品牌、產品、客群（Part 2 三單元統一同一產品） | 分析對象→同業服務商/供應商等 |
| **Part 2 消費者** | 人物誌目標族群與情境 | PM→用戶；客服→高風險客戶 |
| **Part 2 溝通主軸** | KSP+CI 公式情境；Step3 風格維度詞；**Step4 IMC 管道須從品牌實際管道取得**，再依部門命名；Step5 輸出物類型 | 業務→電話/Email/提案/跟進；IMC無資料時保留公版 |
| **Part 3** | JSON 示範的品牌名稱與產品名稱（每個技巧用不同產品）；課程示範/公版內容完整保留 | 可在說明補充部門用途 |
| **Part 4** | 分析目標、儀表板 KPI（ROAS→部門對應指標） | 業務→轉換率/成交週期 |
| **Part 5** | AI 代理情境、品牌視覺背景、對象分類 | 業務→潛力/活躍/流失客戶 |

- [ ] 消費者洞察 Step 1-3：三個 code block 均完整，人物誌對象已依部門調整

- [ ] 文字控制圖像生成助理：主指令 code block 完整

### Step 6：自我審查（Self-Critique）

完成替換與核查後，**在建立 Notion 頁面前**，對整份客製化提示詞進行評分。

**評分維度（各項 1–10 分）：**

| 維度 | 說明 |
|---|---|
| 品牌符合度 | 替換後的品牌資訊是否準確反映學員企業的核心定位與產品？ |
| 部門情境貼近度 | 每個 Part 的情境是否真實反映該部門的日常工作，而非硬套行銷語言？ |
| 指令完整性 | 公版所有 code block（含課程示範）是否完整保留，無遺漏、無誤改？ |
| 產品多樣性 | 各 Part 是否使用不同產品案例？Part 3 各技巧是否各用不同產品？ |
| 洞察深度 | 人物誌、賣點、洞察等描述是否具體且有助於 AI 生成高品質內容？ |
| 資訊潔淨度 | 頁面是否完全不含品牌摘要資訊（標題、說明文字、備註等）？ |

**通過門檻：所有維度皆 ≥ 7 分**

**評分未達標時：**
1. 說明哪個維度低於 7 分及具體原因
2. 自動修正對應問題
3. 重新評分直到通過，方可執行 Step 7

---

### Step 7：建立 Notion 筆記

通過自我審查後，在公版頁面下建立子頁面。

**頁面標題：** `AI解放行銷力 — XX(品牌名)提示詞`

**頁面結構（直接從 Part 1 開始，無任何品牌資訊或說明前言）：**
```
Part 1 AI行銷流新思維
Part 2 行銷策略新高度
Part 3 圖像創作新篇章
Part 4 數據分析新篇章
Part 5 進階應用新可能
```

**禁止出現於頁面的內容：**
- 品牌名稱（無論標題、說明、備註任何位置）
- 品牌摘要、部門說明或學員背景區塊
- 任何「此筆記適用於 XXX 部門」之類的說明文字

建立完成後，向講師回傳頁面連結。

## 彈性擴充原則

若日後課程新增情境（如：簡報生成、程式開發），只需：
1. 辨識新 Part 中的 `[方括號]` 佔位符類型
2. 對應 Step 3 的替換邏輯進行補充
3. 在 Step 5 的核查清單中新增對應 Part 的項目
4. 在 Step 2 的情境對應表中補充新 Part 的部門對應

## 品牌資料或部門資訊不足時的處理方式

| 情況 | 處理方式 |
|---|---|
| 搜尋不到足夠品牌資料 | 先詢問講師補充，確認後再進行替換 |
| 品牌為新創/小眾 | 請講師提供官網或品牌文件 |
| 找不到近期新品資訊 | 改用主力商品，不強行捏造新品資訊 |
| 部門資訊模糊（如「管理職」）| 詢問講師主要日常工作任務為何 |
| 部門跨職能（如業務+PM）| 以比重較高的職能為主，兼顧另一職能的關鍵情境 |
| B2B 企業（產品較抽象）| 聚焦核心服務描述與目標客戶輪廓 |
| 多產品線但來源資料有限 | 優先選最具代表性的 3–5 個產品線分配各 Part |
